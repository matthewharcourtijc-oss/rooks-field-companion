# Field Companion Android launcher (TWA)

This is an isolated Android packaging project for the existing Field Companion PWA.

- PWA origin: https://matthewharcourtijc-oss.github.io/rooks-field-companion/
- Android application ID: `com.harcomindustries.fieldcompanion`
- Packaging: Trusted Web Activity (TWA), generated by Bubblewrap CLI.
- Minimum Android API: 23.
- Browser/runtime: Chrome. The wrapper does not copy the PWA into a separate WebView storage sandbox.

## Data and offline behaviour

The Android launcher opens the existing HTTPS PWA in Chrome's Trusted Web Activity. This is deliberate: the current app's localStorage and service-worker cache remain tied to the existing PWA origin/profile. Do not replace this with a WebView or bundled local HTML without a separately designed and tested data migration.

Offline launch still depends on the PWA having previously cached its app shell in Chrome. This APK does not magically create a second offline copy.

## Signing — required before a verified full-screen release

Create and retain a dedicated HARCOM Field Companion release keystore. **Do not reuse the Vault keystore.** The private keystore and passwords must never be committed.

Configure these GitHub Actions repository secrets:

- `COMPANION_KEYSTORE_BASE64`: base64-encoded dedicated JKS/PKCS12 keystore.
- `COMPANION_KEYSTORE_PASSWORD`: keystore password.
- `COMPANION_KEY_PASSWORD`: private-key password.

The key alias is currently `harcom-field-companion`. If you create a different alias, update the workflow and the `signingKey.alias` field here.

The same release key must be retained for all future APK updates. Losing or changing it can prevent upgrades over an installed copy.

## Digital Asset Links

A signed APK alone does not establish a verified TWA. Android/Chrome also needs the signing certificate SHA-256 fingerprint published at:

`https://matthewharcourtijc-oss.github.io/rooks-field-companion/.well-known/assetlinks.json`

The fingerprint cannot be filled in until the dedicated release keystore exists. The Android build workflow produces a fingerprint report and an `assetlinks.json` candidate as artifacts. Review the fingerprint and publish that file to the PWA site's `.well-known/` directory only after confirming it belongs to the dedicated Companion key.

Until the matching association is live, Chrome may show browser UI (Custom Tab fallback). Do not describe that build as a verified full-screen TWA.

## Build

Run **Build Field Companion Android TWA** from GitHub Actions with `build_release=false` first. That generates and validates the Android project source without requiring a signing key.

After the three secrets are configured, run it with `build_release=true` to produce a signed APK/AAB and Digital Asset Links candidate. Install and test the APK on the Samsung Galaxy S22 before treating it as a release.

## Safety boundaries

- This project does not modify `index.html`, PWA storage, the service worker, or existing backups.
- It has no additional Android permissions enabled by default.
- Never commit a keystore, password, signing key, or generated private credential.
- The APK build is separate from the GitHub Pages deployment workflow.
